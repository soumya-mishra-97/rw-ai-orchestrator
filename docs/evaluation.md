# Evaluation

The brief asks for "numbers, not a demo that felt good". This project makes reliability measurable at three levels:

1. **Pipeline reliability.** How often each handoff succeeds without help, where the pipeline retries or escalates, and what it costs. Measured on the golden scenarios, with several trials per scenario.
2. **Evaluator validity.** Does the judge actually discriminate? This uses a labeled benchmark of seeded defects against known-good artifacts, plus the spec's anti-pattern check.
3. **Evaluator–human agreement.** Blind hand-labels compared with the judge's verdicts: raw agreement, Cohen's kappa and the false-pass count.

Every number below is generated by a script from the audit log of a real run and spliced between the `BEGIN`/`END` markers. **Nothing between the markers is typed by hand.**

> **Status.** This repository was built and tested without Anthropic API credentials. The live-result sections below are therefore still placeholders, and the numbers appear once the commands in "How to reproduce" are run with a key. What *is* verified today, offline, is the reliability engine itself; see "What the offline test suite proves".

## How to reproduce

```bash
export ANTHROPIC_API_KEY=...
make eval                  # 3 scenarios × 3 trials, live; splices EVAL_RESULTS + COST_RESULTS + README headline
make judge-bench           # labeled judge benchmark (10 cases × 3 repeats); add --update-docs to splice
make anti-pattern          # spec §7: flawed Architect injected into a live Scenario 1 run
uv run python -m evals.agreement export evals/reports/<run-dir> --n 20   # blind labeling sheet
uv run python -m evals.agreement score evals/labels/<run-dir> --update-docs
make eval-ablations        # re-run with each cost lever off, for before/after numbers
```

**Budget estimate.** This is not a measurement. It comes from the curated-fixture token sizes at list prices, plus headroom for Sonnet's adaptive-thinking tokens: about $0.10–$0.30 per pipeline run. So `make eval` (9 runs) costs about $1–3 and `make judge-bench` (about 30 judge calls) costs under $0.50.

## Metric definitions

| Metric (spec §8) | Definition | Computed in |
|---|---|---|
| Pass @ attempt 1, per handoff | Runs whose first evaluation at this gate was PASS ÷ runs reaching the gate | `evals/metrics.py::_handoff_stats` |
| Retry rate / escalation rate, per handoff | Runs with ≥ 1 RETRY (or ESCALATE) at this gate ÷ runs reaching it | same |
| Eventual pass without a human | Runs that passed this gate with no escalation | same |
| End-to-end completion rate | Runs reaching `run_completed` with **zero** escalations ÷ all runs | `compute_metrics` |
| Latency | p50 / p95 per LLM call per persona (nearest-rank), and wall-clock per run | `_persona_stats`, `_wall_clock` |
| Tokens | Input (uncached + cache write + cache read) and output, per persona and per run | `_persona_stats`, `_cost` |
| Parse-failure rate | Calls whose output failed Pydantic validation ÷ all calls | `_cost` |
| QA coverage gap | Acceptance criteria with no test case and not declared untestable, per run | `_uncovered_criteria` |
| Judge detection / false-rejection rate | Seeded-defect cases not passed ÷ bad cases; good cases not passed ÷ good cases | `evals/fault_injection.py` |
| Judge consistency | Cases whose verdict differed across repeats | same |
| Evaluator agreement | Human and judge verdicts equal (pass vs not-pass); Cohen's kappa; confusion matrix | `evals/agreement.py` |

In an eval run, an escalation is resolved automatically with `accept_as_is` so that downstream stages still get measured. The run still counts as **escalated** in every metric.

## 2. Does the evaluator discriminate? Labeled judge benchmark

If every handoff passed on the first attempt, that would show the evaluator is not discriminating, not that the agents are flawless. To test that directly, [`evals/fault_cases.py`](../evals/fault_cases.py) builds 10 labeled cases on Scenario 1:

- **4 known-good artifacts**, one per handoff.
- **6 artifacts with one seeded defect each**, of the kind the brief cares about most:

| Case | Seeded defect | Expected catcher |
|---|---|---|
| F1 | PM drops the batch-only, no-API and no-vendor-development constraints and promises real-time blocking | Judge (legacy dimension) |
| F2 | BA writes a 100 ms authorisation-time NFR against a batch-only mainframe and deletes the conflict question | Judge |
| F3 | **Architect assumes a webhook and a REST API on the mainframe** (the spec's anti-pattern) | Judge (critical) |
| F4 | Architect modifies COBOL, although the vendor offers no custom development | Judge (critical) |
| F5 | Dev silently adds a call to a non-existent mainframe REST API | Judge |
| F6 | Risks listed without mitigations | Deterministic pre-gate (0 tokens) |

**Spec §7 anti-pattern check (full pipeline).** `make anti-pattern` runs a live Scenario 1 pipeline in which Architect attempt 1 is replaced by case F3. It passes only if gate 3 does **not** PASS that design. With the default fast-track policy, the expected path is RETRY on a Tier 2 Architect, then either PASS or escalation. The command exits non-zero if the defect slips through.

## 3. Evaluator–human agreement

The protocol:

1. Export a random sample of 20 judged handoffs from a live eval run. The sheet contains the artifacts only; the judge's verdicts are held back in `key.json`.
2. Hand-label each one pass or fail against [`prompts/rubric.md`](../src/sdlc_loop/prompts/rubric.md).
3. Score it.

The false-pass cell (judge PASS, human FAIL) matters most. A false pass lets a defective artifact reach the next stage, while a false reject only costs a retry.

## What the offline test suite proves today

`make test` runs 122 deterministic tests, with no network, in about 3 s. It uses a hand-authored Scenario 1 script ([`demo/scenario1_script.json`](../src/sdlc_loop/demo/scenario1_script.json)) and perturbs it to drive every path through the reliability engine end to end in the real LangGraph graph:

| Behaviour | Test |
|---|---|
| Flawed Architect design → critical flag → Tier 2 retry with feedback and previous attempt → PASS | `test_happy_path_with_one_architect_retry` |
| Persistent critical defect → Tier 2 judge confirms → graph blocks; Dev never runs → human accepts → completes | `test_persistent_critical_defect_escalates_then_human_accepts` |
| Strict policy → escalate on the first critical flag | `test_strict_policy_escalates_on_first_critical` |
| Human retry → guidance reaches the prompt; Tier 2 forced | `test_human_retry_passes_guidance_and_forces_tier2` |
| Human abort → no downstream calls; `run_aborted` audited | `test_human_abort_stops_the_run` |
| Non-critical failures → Haiku, Haiku, **Sonnet** → escalate after 3 attempts; full feedback history on the final attempt | `test_non_critical_failures_exhaust_retries_with_tier_escalation` |
| Borderline Tier 1 score overturned by the Tier 2 judge | `test_tier2_judge_can_overturn_borderline_tier1` |
| Unparseable generated code rejected by the pre-gate with **no judge call** | `test_deterministic_pregate_rejects_without_a_judge_call` |
| Truncated JSON → one repair call → `parse_failure` audited | `test_schema_parse_failure_is_repaired_and_audited` |
| Garbage judge output → fails closed to a human | `test_unusable_judge_output_fails_closed` |
| Paused run resumed from a *new process* via the SQLite checkpointer | `test_run_survives_process_restart` |
| PII never reaches a model call | `test_pii_is_redacted_before_any_model_call` |
| Generated tests actually executed in the sandbox: 3 pass; a planted failure is counted | `test_verifier_executes_generated_tests`, `test_verifier_reports_real_failures` |
| Metrics recomputed from the audit log | `test_metrics_from_audit_log` |

These tests verify the **engine**. They say nothing about model quality, which is what the live sections above are for. `make eval-offline` exercises the whole eval harness end to end with scripted responses, and labels its report "scripted — NOT model quality". The harness refuses to splice offline numbers into these docs.

## Threats to validity

- **Small N.** 3 scenarios × 3 trials is enough to find the weakest handoff, not to claim a precise rate. Rates are reported with their denominators so readers can judge for themselves.
- **Same-family judge.** Claude judges Claude, and self-preference bias is plausible. The human-agreement study and the seeded-defect benchmark (ground truth by construction) are the controls for it.
- **Author-built labels.** I wrote the seeded defects and the fixtures, so they measure the failures I anticipated. Unanticipated failure modes show up only in the human-agreement sample.
- **Counterfactual tokens are estimates.** The full-history context size uses a ~4-characters-per-token estimate because that context is never sent. The `make eval-ablations` run with `--context-policy full_history` gives the measured version.
